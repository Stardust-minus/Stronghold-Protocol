# 完整干员预设

本 fork 的“干员调配”保留技能／模组、干员持有（替补）及自选编队编辑页签，外观仍在干员详情中选择。所有页签现在共用“导出预设／导入预设”，不再单独导出皮肤或各页签的设置。

## 包含哪些配置

一份完整预设包含：

- `entries`：普通棋子的技能选择与精锐模组选择。
- `ops`：每个支持的干员的潜能／练度配置；与显示外观分离，使用既有干员设置校验。
- `notOwned`：未持有的普通干员，沿用原官方指定替补规则。
- `diy`：四个自选编队／助战名额的干员及允许选择的技能、模组。
- `skins`：干员对应的已收录时装 ID；不包含图片、骨骼、动画或任意素材 URL。

外观仍是 display-only，技能、模组、持有和自选编队仍使用原校验与玩法语义。预设不含房间人数、难度、队友设置、帐号身份、会话凭据、当前战斗或棋盘状态。

## 使用与兼容

1. 在大厅、好友房或原有信息确认阶段打开“干员调配”。
2. 任意页签点击“导出预设”，复制 JSON 或下载文件；默认空配置也可以导出。
3. 其他设备或浏览器点击“导入预设”，粘贴文本或选择文件。
4. 完整文件会替换所有包含的配置项，显式空项恢复对应默认值；旧文件没有 `ops` 时保留当前潜能／练度。

旧 `stronghold.loadout`、`stronghold.ownership`、`stronghold.diy` 和 `stronghold.skins` 文件仍可导入，只更新它们原先代表的单项，其他配置保持不变。原受支持的旧技能 bare-map／stored 形式、持有数组／stored 形式及自选 stored 形式也保留兼容。旧纯技能配置若没有任何当前可用的非默认条目，仍拒绝覆盖，不借此清空现有选择。

## 格式与校验

新文件的 `kind` 是 `stronghold.operator-preset`，`v` 是 `1`，并包含 `exportedAt`、`entries`、`notOwned`、`diy`、`skins`；支持潜能／练度的版本还导出 `ops`。这是与旧文件兼容的可选项：没有 `ops` 的旧完整预设或旧技能文件保持当前潜能／练度不变，显式空 `ops` 恢复其默认值。旧客户端不具备该设置时不会应用它，跨版本导入需核对实际生效项目。`exportedAt` 仅说明导出时间，不是服务端权威版本。

- 文本按 UTF-8 限制在 256 KiB，文件在读取前检查大小。
- 未知类型、较新版本、缺少完整配置项或错误的顶层结构拒绝。
- 每个包含的配置项先按原数据和允许名额校验，缺少游戏数据时不清空设置。
- 某个非空项在当前版本完全不可用时，整个导入拒绝，不先应用另一项。
- 原有合法部分的容错清理保留，并提示未导入项；不会信任文件给出的技能、时装路径或名额权限。
- 原型污染键不进入最终配置。
- 所有项通过后只发布一次完整客户端内存更新，再由原有同步引擎处理。保留旧存储键与原 `room.*` 消息，不宣称跨多个 localStorage 写入或多个服务端消息构成事务；存储被浏览器阻止时仍保留本会话的整体内存配置。

## 本局生效边界

统一预设没有放宽锁定规则：技能／模组保留 INFO_CHECK 截止边界，持有、自选编队及外观保留各自原有开局锁定规则。对局中某项已经锁定时，修改仍供下一局使用，不覆盖正在运行的对局快照。各页签和外观栏继续显示各自同步状态。

## 验证边界

相关测试应覆盖完整、旧单项及无效预设，缺数据时不持久化、不更新内存，以及旧皮肤导入不依赖游戏数据的兼容行为。浏览器检查还应覆盖跨页签导出、跨浏览器导入、刷新恢复、原同步与观战私有边界。

本说明不代表某个环境的上线状态。一次受控战斗或手机视口模拟不能证明全部干员技能/时装像素一致、实体设备兼容、自然整局平衡或生产容量；局部翻译检查也不等于完整语言包通过。具体验收日志和发布记录应保存在私有运维档案，不写入公开使用说明。
